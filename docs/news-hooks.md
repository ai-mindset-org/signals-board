# новостные зацепки – каркас

Борд показывает, что залетело у авторов темы. Зацепки идут с другой стороны:
берут новости темы, о которых уже пишут несколько изданий, и смотрят, что по ним
сняли на YouTube и у авторов борда. Если никто не снял или смотрят мало, значит
есть окно снять своё первыми. Модель предлагает, какой ролик снять, в каком
формате и с какой первой фразы.

Это каркас: сбор, поиск, вердикт, подача, вкладка на сайте и workflow работают и
проверены на живых данных 22.10.2026. Что доделать — внизу.

## Как устроено

```
ClawDigest trending ──► жирные сюжеты ──► поиск роликов ──► вердикт ──► подача моделью ──► вкладка «новости»
(каждые 15 мин)         (≥ 2 издания)     YouTube + борд    окно/рано/   ролик, формат,      site/data/news.json
                                          (TikTok – TODO)   залетает     первая фраза
```

| файл | что делает |
|---|---|
| `scripts/news.mjs` | новости ClawDigest → поиск YouTube и совпадения с постами борда → вердикт; пишет `site/data/news.json` только если сюжеты изменились |
| `scripts/news-compose.mjs` | подача моделью для сюжетов без подачи; заодно поисковые фразы на английском, по ним `news.mjs` ищет в следующий прогон |
| `site/news.js` | вкладка «новости»: сначала «окно», потом «рано», потом «залетает» |
| `.github/workflows/news.yml` | каждые 15 минут: зацепки → подача → проверка → коммит и Pages, только при изменениях |
| `signals.config.json` → `news` | включатель и пороги |

### Новости

`GET https://clawdigest.live/api/v2/trending?hours=24&category=ai&limit=20` с
`X-API-Key` (секрет `CLAWDIGEST_API_KEY`). Без ключа берётся публичный
`/api/trending`, ответ тот же. ClawDigest склеивает одну новость из разных
изданий в сюжет; `story_sources` — сколько изданий о ней написали. «Жирная»
новость — `story_sources >= min_sources` (по умолчанию 2). Free-ключ даёт 100
запросов в час, прогон тратит один.

### Поиск роликов

- **YouTube**: страница поиска за неделю, ключ не нужен. Берутся обычные ролики
  (просмотры и возраст) и Shorts (только просмотры). Запросов два: название
  продукта из заголовка («Claude Duet») и имена плюс слова заголовка. Со второго
  прогона добавляются фразы модели.
- **TikTok**: без ключа поиска нет, выдача TikTok грузится в браузере
  подписанными запросами (проверено 22.10). Сейчас вместо поиска берутся ролики
  авторов борда из `signals.json`, совпавшие с новостью. Платный поиск
  подключается в `searchTiktok()`, ролики возвращаются в том же виде, что у
  `searchYoutube()`.
- **Совпадение**: нужно хотя бы два общих слова, и одно из них должно быть именем
  собственным: «AI agent» без «Claude» и «Duet» не считается роликом про Claude
  Duet. Мера — доля общих слов от более короткого из двух текстов.

### Вердикт

| код | на борде | условие |
|---|---|---|
| `gap` | окно | роликов по новости нет |
| `early` | рано | ролики есть, у лучшего меньше `big_views` (10 000) просмотров |
| `covered` | залетает | у лучшего ролика `big_views` и больше |

Внутри сюжета ролики отсортированы по просмотрам в час. Когда вердикт меняется,
подача пересобирается.

Если YouTube не ответил ни на один запрос сюжета, вердикт не ставится: пустая
выдача из-за сбоя дала бы ложное «окно». Сюжет остаётся как был и ищется в
следующий прогон.

## Включить

```bash
# включить: переменная репозитория (или news.enabled: true в signals.config.json)
gh variable set NEWS_ENABLED --body 1 --repo ai-mindset-org/signals-board
gh secret set CLAWDIGEST_API_KEY --repo ai-mindset-org/signals-board   # необязательно
gh workflow run news.yml --repo ai-mindset-org/signals-board
```

Ключ модели — тот же `OPENROUTER_API_KEY`, что у разбора. Подача — один вызов
на прогон и только когда есть сюжеты без подачи; по оценке `compose.mjs` вызов
на Sonnet стоит около $0.02.

Руками:

```bash
node scripts/news.mjs --story "Walmart is inviting AI agents to shop for you"   # один заголовок
node scripts/news.mjs --dry-run                                                  # весь прогон без записи
node scripts/news.mjs && OPENROUTER_API_KEY=… node scripts/news-compose.mjs && node scripts/check.mjs
```

## Настройки `news`

| ключ | по умолчанию | смысл |
|---|---|---|
| `enabled` | `false` | без него (или переменной репозитория `NEWS_ENABLED=1`) `news.mjs` ничего не делает. Конфиг копируется в репозитории из шаблона, поэтому в шаблоне выключен, а пример включён переменной |
| `category` / `region` | `ai` / все | фильтр ClawDigest |
| `hours` | 24 | окно новостей |
| `min_sources` | 2 | сколько изданий делают новость жирной |
| `max_new_per_run` | 4 | сколько сюжетов искать за прогон (каждый — два запроса к YouTube) |
| `refresh_hours` | 6 | когда перепроверять уже найденный сюжет |
| `keep_hours` | 72 | сколько держать сюжет на борде |
| `search_window_hours` | 72 | ролики старше к новости не относятся |
| `min_relevance` | 0.5 | порог совпадения |
| `big_views` | 10000 | порог «залетает» |

## Что доделать

- [ ] **TikTok-поиск**: выбрать провайдера (Apify, RapidAPI или свой браузер) и
      реализовать `searchTiktok()`, ключ — секретом.
- [ ] **Новостной фон в разборе**: передать в `compose.mjs` 3–5 главных сюжетов
      недели из `news.json`, чтобы «почему залетело» видело контекст, и строка с
      заголовками на дайджесте. На борде AI Mindset (lab-sites) сделано 22.10:
      `collect.mjs` → `news`, `compose.mjs`, строка над плиткой.
- [ ] **Уведомление команде**: новый сюжет с вердиктом «окно» → сообщение в
      рабочий чат (через бота команды), пока окно не закрылось.
- [ ] **Общий вызов модели**: `compose.mjs` и `news-compose.mjs` вызывают модель
      одинаково, вынести в `scripts/llm.mjs`.
- [ ] **Пороги** `big_views`, `min_relevance`, `min_sources` подобрать после
      недели прогонов.
- [x] **Шаблон**: зацепки включаются переменной репозитория `NEWS_ENABLED=1`,
      в конфиге шаблона выключены. У выключенного репозитория прогон раз в 15
      минут доходит только до проверки включателя и ничего не тратит.
